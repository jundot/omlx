# Cluster ladder validation — 2026-11-08

Live run on the four-Mac validation cluster after the helper4 rollout. The
installed app is signed but not notarized (rollout did not wait for Apple).
The app is running with the new `wizardState`, MTP inventory, disk probe,
absolute rank-0 shim, model-inventory default and recommendation filter.

## Infrastructure prepared during the ladder

- **Full mesh pairing:** `.12`, `.13` and `.14` were each paired with the M5
  (`172.16.1.11`) and with each other. A Studio elected as coordinator can now
  reach every selected Studio.
- **Self host keys:** `.12`/`.13`/`.14` had stale entries for their *own*
  address. Coordinator staging resolves the model directory over SSH to its own
  LAN address; the stale self key caused `REMOTE HOST IDENTIFICATION HAS
  CHANGED` and `staging_failed`. Removing the self entries fixed 3/4-Mac
  staging. Keep this in mind after a reinstall/rename.
- **DeepSeek source copy:** `.12` did not have DeepSeek. The assistant's
  `model_source()` skipped the local worker (`target.local`) when `.12` was
  coordinator, so apply returned `model_source_missing`. The source code is
  fixed (local worker is a valid source; test added), but this installed app
  still contains the old logic. For this live run the model was copied with
  `rsync` and `.12`'s models were reloaded before apply.

## Open items found during the ladder

1. **Source selection for a remote coordinator** — fixed and installed in
   helper5 (`model_source()` no longer skips a local worker), with a
   regression test.
2. **Reload after staging** — fixed in helper5: the coordinator is reloaded
   before `prepare` in apply and start; fake test asserts the reload call.
3. **Self host key for coordinator staging** — fixed in helper6:
   `is_local_host()` recognizes the machine's own interface addresses, so a
   coordinator resolves its own model locally instead of SSHing to itself.
4. **Full mesh pairing** — helper6 adds an apply preflight: the coordinator's
   own device snapshot must contain every selected peer, otherwise the
   operation fails `node_not_paired` / `pair_mac` before staging. Automatic
   pairing across Studios is still a separate feature.
5. **Qwen documentation** — `PHASE-2B-RUN.md` §16 corrects the stale §14.2 C
   note; the non-PP rule itself is unchanged.
6. **2-Mac non-adjacent pairs** — `topology_incomplete` + consent fallback is
   correct; the fallback chooses the best adjacent 2-Mac set, not the
   requested non-adjacent pair.
7. **GLM 32k admission margin** — fixed in helper6: rank 0 reserves 256 MiB
   for supervisor/live-start drift, never below the measured p05 floor.
