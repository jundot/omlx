### Assistant UI: one flow, one page

The Cluster tab now renders **exactly one screen per assistant state** —
`start`, `check`, `plan`, `launch`, `ready`, `stopped`, `failed`, `choose` — each
gated by `assistantScreen()` on top of the existing `assistantState()` machine.
No backend state, route, poll or SSE was added.

- **Assistant / Manual setup** is one remembered preference
  (`clusterV2.mode`, default Assistant). Today's wizard blocks are byte-identical
  behind the manual wrappers; the pairing surface, device grid and plan form are
  one click away.
- **A failure owns the card**: plain-language title, the backend's own cause,
  exactly one primary action from `error.action`, a secondary retry that
  re-enters the failed step, and the branch affordances (2-Mac consent,
  free-space picker) inside it. A failed `start` retries **in place** against the
  applied deployment (`operation_id`), never a forced re-apply.
- **Change model or context** is the back affordance: a model change re-measures
  model-bound, a context-only change re-plans, and both reuse the fresh hardware
  measurement. `stale` is derived from the frozen plan inputs (model, context,
  pin, node selection, MTP, execution profile, measurement id, 2-Mac consent);
  Start setup re-plans a stale plan instead of applying it.
- **Ready** keeps the `assistantReady()` endpoint gate, hides any endpoint when
  stopped, shows the measured line only when `observed` exists, and collapses
  tuning / MTP depth / probe into one **Performance** section. A tune failure is
  repeated on the card, never only inside the collapsed details.
- The catalogue is loaded before the entry measurement, so the recommendation's
  candidates and the MTP head no longer depend on the manual plan step.

Spec and decisions: `docs/cluster-assistant/ASSISTANT-UI-SPEC-2026-11-16.md`
(implemented in U1–U6; log and deviations in
`ASSISTANT-UI-IMPLEMENTATION-PLAN-2026-11-16.md` §7).

Validation: `apps/omlx-web/tests` **578 passed / 3 deselected** (focused three
