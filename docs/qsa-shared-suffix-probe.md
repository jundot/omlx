# Shared QSA prefixes in serving

`qwen4_qsa_shared_prefix_enabled` enables the Qwen4 family’s immutable-prefix/private-suffix cache for one model. The per-model setting is reload-bound and default off. The family’s cache conversion and the scheduler’s generic singleton preparation hook select the route in the real `BatchGenerator`, including restored warm caches. The ordinary QSA cache and attention remain the reference when the setting is off.

Each block-aligned prefix retains KV, raw indexer keys, positions and pooled summaries once. Each request owns a small writable suffix. Joins, extraction, cloning, filtering, cancellation and speculative rollback retain prefix ownership and operate on independent suffix banks. Array clones create new MLX wrappers over existing allocations so slice assignment cannot rebind another request’s cache. Projection, block selection, selected-KV SDPA and output projection retain the ordinary batch geometry; only storage and bounded gathering operate per row. Full KV and raw-history concatenation is absent from this attention path. Small pooled-summary banks and selected-KV workspaces are batched.

Supported text positions include rank-two positions and the native three-axis MRoPE representation when every axis equals the row’s ordinary absolute positions. Supplied rotary cos/sin must exactly match the loaded layer’s generated values, and are then passed to the existing projection helper. Media axes, custom positions, custom rotary values, custom masks and initial left padding explicitly materialize into the ordinary batch implementation. Persistence handlers also explicitly materialize exact ordinary QSA state; deserialization restores ordinary caches without importing a transient owner stamp. Fallback retains per-row scope and loaded-owner metadata, pending right-padding transactions, and the extract/filter/extend ABI. Joins during unfinished transactions and rollback into an immutable prefix fail before mutation.

A live prefix belongs to one loaded attention/indexer pair, its current parameter-array identities, and one immutable source lineage. Replacing a parameter or moving a live cache to another layer fails closed. Model-owned attention binds restored unowned caches before activation; the existing prefix-cache engine remains responsible for selecting state under the correct durable model/revision identity. This is a loaded-process ownership check, not a new durable checkpoint attestation format. The generic request handoff preserves the request’s media-cache scope when provided, and sharing requires matching scope. These attributes survive cloning, extraction, fallback and rejoining; they are deliberately absent from persisted tensors.

New restored rows do not carry authoritative shared-block identity in this cache ABI. Activation therefore interns candidate prefixes by exact equality of KV, raw keys and positions within the current batch, after owner and scope checks. A longer row may reuse a shorter aligned prefix while keeping its additional tail private. The equality scan and host synchronization happen on activation or a late join, rather than each decode step; worst-case work is quadratic in batch size times prefix length. Text-position proofs and optional rotary equality checks also synchronize small request-shaped arrays. This implementation establishes correctness and storage sharing, and may add latency. A short prefix with only two rows can retain more capacity than the ordinary compact batch because the shared views hold the original prefill allocation slabs; the memory benefit depends on sufficiently long prefixes and enough reuse. It makes no general memory or throughput claim.

`SharedBatchQSAKVCache.shared_prefix_metrics()` exposes `shared_attention_calls` (counted per shared row), activated `shared_rows`, `prefix_comparisons`, `prefix_comparison_tokens`, `prefix_reuses`, `rotary_comparisons`, `materializations`, current row/shared-row counts, retained tensor bytes and fallback status. Retained tensor bytes conservatively count complete source allocation capacities held by prefix views and deduplicate a shared base; they are not allocator peak memory. These counters distinguish configuration from observed engagement.

Local CPU validation passes 38 new tests: real family decode/verify widths 1/3/4, exact logical cache state, setting-driven main/MTP cache creation, restored-prefix reuse, native MRoPE and supplied rotary values, actual `BatchGenerator` decode/late join/cancel, complete greedy-output parity under the same request schedule, native MTP verification, ownership/scope boundaries, padding transactions, persistence and clone isolation. The original frozen experiment’s broader CPU cache regressions passed 250 tests with 12 Metal-only skips. Its final GPU regressions passed 561 tests with 43 skips for unavailable native extension kernels.

Controlled M5 GPU measurements used one actual trained mixed-quantization checkpoint attention layer, synthetic hidden inputs, batch eight, prefix 4096, 32 decode steps and three alternating reference/shared pairs. The first four decode steps were excluded from steady timing. Every decode, three-row verify, rollback-by-two and subsequent decode output was bit-identical to the ordinary batch reference. All implementation hashes matched the frozen candidate. Measured results were:

| Measurement | Ordinary | Shared |
| --- | ---: | ---: |
| Retained cache tensor capacity | 82,519,168 bytes | 24,289,280 bytes |
| Median steady attention step | 1.4600 ms | 2.0071 ms |
| Allocator peak across the three runs | 302,250,595 bytes | 249,825,843–249,924,403 bytes |

At this tested shape, sharing reduced retained cache capacity by about 70.6% while attention was about 37.5% slower. These are bounded one-layer performance results, not a general model throughput claim.

The real full indexed checkpoint, with MTP off, generated the same 16 tokens per request through the VLM adapter and `BatchGenerator` at batch eight/prefix 4096. A final frozen-implementation repeat confirmed sharing in all twelve QSA layers: eight active shared rows, seven prefix reuses and zero fallback/materialization. Measured allocator peaks were 75,908,313,579 bytes for the ordinary run and 75,262,817,717 bytes for the final shared repeat. Full-model timing was not a controlled throughput comparison. Batch two/prefix 512 also matched outputs and engaged every QSA layer, but retained more cache capacity than the ordinary compact batch; sharing is consequently a memory option for suitable workloads, not an automatic improvement.

The implementation is finished and observed in actual serving. It remains experimental, opt-in and not declared broadly qualified or selected by default. GPU measurements establish the specific correctness, engagement and tradeoffs above; they do not establish general media support or universal gains.

The implementation is adapted from the Apache-2.0-licensed mlx2 experiment. Local source and validation provenance are recorded in `provenance/qsa-shared-prefix.json`; frozen source, detailed receipts and scripts are available in the [public evidence repository](https://github.com/pierre427/omlx-qsa-shared-prefix).
