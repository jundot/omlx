# oMLX macOS app packaging

This directory builds the venvstacks Python layers that the Swift app embeds. The `.app` itself is built by [`apps/omlx-mac/Scripts/build.sh`](../apps/omlx-mac/Scripts/build.sh), which takes the `_export/` tree from here.

## Requirements

- macOS 15.0+ (Sequoia), required by MLX >= 0.29.2
- Apple Silicon (M1 to M5)
- Xcode 26.5+ with the Metal toolchain (`xcodebuild -downloadComponent MetalToolchain`) for the custom kernels
- Python 3.11+ on the host, plus venvstacks from `make dev`, `uvx`, or `pipx run`

## Build

From the repo root:

```bash
make app    # build.sh release --with-custom-kernel
```

`make app` re-exports the venvstacks layers when their inputs changed, builds the Swift app, bundles all five custom kernels, and stages `apps/omlx-mac/build/Stage/oMLX.app`.

Other `build.sh` modes:

```bash
apps/omlx-mac/Scripts/build.sh release --rebuild-donor     # force a venvstacks re-export
apps/omlx-mac/Scripts/build.sh release --no-rebuild-donor  # reuse _export/ even if stale
apps/omlx-mac/Scripts/build.sh swift                       # rebuild only the Swift app
apps/omlx-mac/Scripts/build.sh release --bare              # Swift shell without the Python embed
```

`make app` passes `--with-custom-kernel`. Add it yourself when you call `build.sh` directly and want the kernels in the bundle.

To work on the layers alone:

```bash
python packaging/build.py --venvstacks-only     # re-export the layers
python packaging/build.py --print-fingerprint   # input fingerprint build.sh uses to decide on a re-export
```

## What goes into the bundle

`build.sh` copies the server package to `Contents/Resources/omlx` and the web UI package to `Contents/Resources/omlx_web`, and fails if the web UI templates are missing. Python and the dependencies come from the venvstacks export:

| Layer | Contents |
|-------|----------|
| Runtime (`cpython-3.11`) | Python 3.11 |
| Framework (`mlx-base`) | Generated by `build.py` from the `[project]` dependencies and the `[bundle]` extra in `pyproject.toml` |

There is no application layer. The Swift app is the application.

## Output

```
packaging/
├── _build/         # venvstacks intermediate layers
├── _export/        # venvstacks export, embedded into the .app
├── _wheels/        # cached local wheels (e.g. mlx + mlx-metal pins)
└── requirements/   # venvstacks lock files
```

## Installing a local build

Drag `apps/omlx-mac/build/Stage/oMLX.app` to `/Applications`, or `open` it in place. The app shows up in the menu bar. Finish the first-run wizard (storage and API key), then start the server.

The DMGs on the [Releases](https://github.com/jundot/omlx/releases) page come from a maintainer pipeline outside this repo. This section is for developers building from source.
